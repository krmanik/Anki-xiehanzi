# Contributing to Anki xiě hànzì (写汉字)

Thanks for taking the time to contribute! :sparkles: Whether you're fixing a
typo in a definition, reporting a bug, or improving the web app, this guide
covers how the project is laid out and how to get your change merged.

## What this repo is

The project has three loosely-coupled parts:

1. **The web app** — a [SvelteKit](https://svelte.dev/) + [Vite](https://vite.dev/)
   static site: the homepage, docs, and the browser-based deck generator at
   `/create`. All app code lives in `src/`.
2. **Pre-built Anki decks** — the large `*.apkg` files published via
   [GitHub Releases](https://github.com/krmanik/Anki-xiehanzi/releases). These are
   generated by the offline pipeline (`main.ipynb` + `HSK Wordlist/` +
   `card templates/`), **not** by the web app.
3. **HSK word data** — the
   [HSK-3.0-words-list](https://github.com/krmanik/HSK-3.0-words-list) git
   submodule. Words, pinyin, zhuyin and meanings live here.

> **Where does my fix go?** Wrong word, pinyin, zhuyin or meaning → the
> [HSK-3.0-words-list](https://github.com/krmanik/HSK-3.0-words-list) repo. Bug
> or feature in the website / deck generator → this repo.

## Reporting issues

Before opening an issue,
[search existing issues](https://github.com/krmanik/Anki-xiehanzi/issues) — it may
already be reported. If not, open a new one with a relevant
[issue form](https://github.com/krmanik/Anki-xiehanzi/issues/new/choose).

- **Wrong word data** (meaning, pinyin, zhuyin): file against
  [HSK-3.0-words-list](https://github.com/krmanik/HSK-3.0-words-list).
- **Website / generator bug**: file here. Include browser, steps to reproduce,
  and a screenshot if relevant.

We don't pre-assign issues — find one that interests you and open a PR.

## Development setup

You need **Node.js 20** (the CI runs on 20; the minimum is 18).

```bash
git clone --recurse-submodules https://github.com/krmanik/Anki-xiehanzi.git
cd Anki-xiehanzi
npm install
npm run dev          # vite dev server → http://localhost:5173
```

Already cloned without `--recurse-submodules`? Pull the word list in with:

```bash
git submodule update --init --recursive
```

### Commands

```bash
npm run dev          # vite dev server
npm run build        # static build → build/ (SPA, 404.html fallback)
npm run preview      # serve the production build
npm run check        # svelte-kit sync + svelte-check (typecheck)
npm test             # vitest run (both projects)
npm run test:watch   # vitest watch
```

Run a subset of tests:

```bash
npx vitest run src/lib/tone.test.ts   # one file
npx vitest run --project node         # fast pure-logic tests only
npx vitest run --project dom          # jsdom + compiled Svelte tests
```

Tests split into two vitest projects: **node** (pure logic, no DOM —
`src/**/*.test.ts`) and **dom** (jsdom + compiled Svelte — `*.svelte.test.ts`).
Keep pure logic in `*.ts` so it lands in the fast `node` project; only
component / interaction tests get the `.svelte.test.ts` suffix.

## Working on the deck generator

The generator (`/create`) is layered so the correctness-critical parts stay pure
and unit-tested, and the exported `.apkg` byte output doesn't drift:

- `src/lib/deckTemplate.ts` — **pure** card layout, element ordering, groups,
  CSS. No genanki-js / sql.js / DOM. Heavily unit-tested.
- `src/lib/deck.ts` — the impure orchestrator (genanki-js, sql.js, jieba-wasm,
  edge-tts). **Model IDs, templates and media list must stay identical** to the
  original — changing them breaks existing users' cards.
- `src/lib/cardPresets.ts`, `tone.ts`, `cardThemes.ts`, `dict/` — pure data /
  builders plus the impure dictionary layer.
- `src/routes/create/+page.svelte` — the UI orchestrator; most UI lives in
  `src/lib/components/`.

If you touch card templates, model IDs or the media list, **run `npm test`** —
those are byte-pinned in tests for a reason.

See [CLAUDE.md](CLAUDE.md) for the full architecture notes and build gotchas
(Tailwind source scanning, Lucide deep imports, the GitHub Pages base path, etc.).

## Pull requests

1. Fork the repo and create a working branch off `main`.
2. Make your change. Run `npm run check` and `npm test` before pushing.
3. Open a PR against `main`. Describe what changed and why, and
   [link the issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/linking-a-pull-request-to-an-issue)
   if you're solving one.
4. Enable
   [maintainer edits](https://docs.github.com/en/github/collaborating-with-issues-and-pull-requests/allowing-changes-to-a-pull-request-branch-created-from-a-fork)
   so the branch can be updated for merge.

A maintainer will review and may request changes. Once merged, your contribution
ships on [Anki xiehanzi](https://krmanik.github.io/Anki-xiehanzi). Thank you!
:tada:
